Drag & Drop Redesign — Which approach?

Pick the architecture that fits how you want it to feel. We'll fully rewrite SectionList.tsx based on this choice.

A

dnd-kit Multi-Container (Proper Pattern)

Follow dnd-kit's official multi-container sortable example exactly. Two independent SortableContexts share one DndContext. A customCollisionDetection function first checks pointerWithin (are you physically inside a container?), then falls back to rectIntersection. onDragOver moves items between lists live. DragOverlay shows the ghost card. The original dragged item is invisible while dragging.

Pros

  • Battle-tested by the dnd-kit team
  • Smooth live reordering in both columns
  • Cross-column drops land exactly where you release

Cons

  • More code — custom collision detection
  • Need careful state sync (local ↔ parent)

Recommended — most predictable feel

B

Replace dnd-kit with @hello-pangea/dnd (DnD classic API)

Drop dnd-kit entirely. Use @hello-pangea/dnd (the maintained fork of react-beautiful-dnd). Wrap both columns in a DragDropContext. Each column is a Droppable. Each section is a Draggable. Cross-column drag is a first-class feature — onDragEnd tells you exactly which droppable the item came from and landed in. No custom collision detection needed.

Pros

  • Extremely simple API for multi-list
  • Cross-column drag works out of the box
  • No onDragOver complexity

Cons

  • Adds a new dependency
  • Less flexible for custom visuals
  • Slightly different drag feel vs dnd-kit
C

Keep dnd-kit, Simplify Architecture

Keep dnd-kit but radically simplify: remove DroppableContainer entirely. Use only SortableContext per column with a single flat item list. Track activeId and which container it came from. On dragEnd, look at the over.id to determine destination — no onDragOver at all. Add a DragOverlay. Accept that cross-column drops land at the end of the target list (no position-insertion during drag).

Pros

  • Smallest amount of code
  • No complex state management

Cons

  • No live reordering during cross-column drag
  • Items always land at end of target column
